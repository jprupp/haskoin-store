Output of `haskoin-store-bench merge 100000 20000 256 DIR +RTS -N4 -A64m`,
2026-11-15. The three numbers are the defaults, and DIR is a directory on
tmpfs.

AMD Ryzen 9 3900X, RocksDB 11.1.1, the database on tmpfs, Bloom filters on.
What it measures, and how the database is built, is at the top of
bench/Merge.hs: reads of keys that have a whole value at the last level
and none, one, three or six merge records over it, each in a table file of
its own, and then the same reads once everything is compacted.

`haskoin-store-bench merge 100000 20000 1 DIR +RTS -N4 -A64m`: with a block
cache of 1 MiB, so that every block looked into is fetched from the file
and decompressed again, as on a store whose cache is a fraction of its
database. The files are in memory all the same: on a disk, each table file
that has a merge record of the key is one more block to read from it.
